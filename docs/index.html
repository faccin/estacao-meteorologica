Lista de materiais

Heltec WiFi LoRa 32 V3
ESP32-S3 com LoRa, OLED 0.96", gerenciamento de bateria
Orange Pi Zero 2W
2GB RAM, slot microSD, WiFi onboard. Fonte USB-C 5V/2A
BMP280
Módulo I2C — pressão (300–1100 hPa) e temperatura. ~R$ 12
DHT22
Umidade (0–100%) e temperatura. Resistor pull-up de 10 kΩ incluído na maioria dos módulos
Protoboard + jumpers
Para a montagem sem solda. Jumpers macho-fêmea para os módulos
Cartão microSD
16 GB classe 10 para o Armbian na Orange Pi
Opcional para off-grid: painel solar 5W + controlador de carga + bateria 18650 para o Heltec, e painel 10W + powerbank para a Orange Pi.

Ligações elétricas

Os dois sensores conectam diretamente no Heltec V4. O BMP280 usa o barramento I2C (dois fios de dados + alimentação) e o DHT22 usa um pino digital.

Tabela de conexões

SensorPino do SensorPino do Heltec V4Observação
BMP280VCC3.3VAlimentação 3.3V
BMP280GNDGND
BMP280SDAGPIO 41I2C Data
BMP280SCLGPIO 42I2C Clock
DHT22VCC (pino 1)3.3VAlimentação 3.3V
DHT22DATA (pino 2)GPIO 7Pull-up 10 kΩ para 3.3V
DHT22GND (pino 4)GNDPino 3 não conecta
Atenção: O DHT22 em módulo (plaquinha azul) já tem o resistor pull-up embutido. Se estiver usando o componente avulso, coloque um resistor de 10 kΩ entre DATA e VCC.

Firmware do Heltec V4

3.1 — Preparar o Arduino IDE

  1. Abrir o Arduino IDE. Em Arquivo → Preferências, adicionar esta URL no campo "URLs adicionais para Gerenciadores de Placas": 
    https://github.com/Heltec-Aaron-Lee/WiFi_Kit_series/releases/download/0.0.9/package_heltec_esp32_index.json
  2. Em Ferramentas → Placa → Gerenciador de Placas, buscar Heltec ESP32 e instalar o pacote Heltec ESP32 Dev-Boards.
  3. Em Ferramentas → Placa, selecionar WiFi LoRa 32 (V3) / Wireless Shell (V3).
  4. Instalar as bibliotecas via Ferramentas → Gerenciar Bibliotecas: 
    Adafruit BMP280 Library
Adafruit Unified Sensor
DHT sensor library    (por Adafruit)
ArduinoJson           (por Benoit Blanchon)

3.2 — Carregar o firmware

  1. Abrir o arquivo firmware/estacao_heltec/estacao_heltec.ino
  2. Verificar as configurações no topo do código: 
    const char* WIFI_SSID     = "EstacaoMeteo";    // nome do hotspot
const char* WIFI_PASSWORD = "meteorologia";    // senha
const char* SERVIDOR_URL  = "http://192.168.4.1:5000/api/dados";

const unsigned long INTERVALO_LEITURA = 60000;  // 60s entre leituras

#define SDA_PIN   41    // I2C Data  (BMP280)
#define SCL_PIN   42    // I2C Clock (BMP280)
#define DHT_PIN   7     // DHT22 data
  3. Conectar o Heltec V4 via USB-C ao computador.
  4. Selecionar a porta serial em Ferramentas → Porta.
  5. Clicar em Upload (seta →).

3.3 — O que o firmware faz

Ao ligar, o Heltec tenta conectar no WiFi EstacaoMeteo (o hotspot da Orange Pi). A cada 60 segundos, lê temperatura e pressão do BMP280 via I2C, umidade do DHT22, mostra os valores no display OLED, e envia um JSON via HTTP POST para o servidor Flask. Se o WiFi cair, reconecta automaticamente. O display mostra também um contador de envios bem-sucedidos e falhas.

Para testar sem a Orange Pi: abra o Monitor Serial (115200 baud) — o firmware imprime cada leitura como JSON, útil para verificar se os sensores estão funcionando antes de montar o sistema completo.

Preparar a Orange Pi

4.1 — Gravar o sistema operacional

  1. Baixar o Armbian (Debian Bookworm, servidor) para Orange Pi Zero 2W em armbian.com/orange-pi-zero-2w
  2. Gravar no cartão microSD com balenaEtcher ou dd.
  3. Inserir o cartão na Orange Pi e ligar com fonte USB-C 5V/2A.
  4. No primeiro boot, conectar via cabo Ethernet (ou WiFi temporário) e SSH: 
    ssh root@<IP-da-Orange-Pi>
# Senha padrão: 1234 → criar usuário e senha nova

4.2 — Instalar pacotes

sudo apt update && sudo apt upgrade -y
sudo apt install -y python3 python3-pip hostapd dnsmasq
pip3 install flask --break-system-packages

Configurar o hotspot WiFi

A Orange Pi vai criar uma rede WiFi própria. Os alunos conectam nessa rede para acessar a interface — sem precisar de internet.

5.1 — IP estático na interface WiFi

sudo nmcli con add type wifi ifname wlan0 con-name hotspot \
  autoconnect yes ssid EstacaoMeteo
sudo nmcli con modify hotspot \
  802-11-wireless.mode ap \
  802-11-wireless.band bg \
  ipv4.method shared \
  ipv4.addresses 192.168.4.1/24 \
  wifi-sec.key-mgmt wpa-psk \
  wifi-sec.psk "meteorologia"
sudo nmcli con up hotspot
Alternativa (se o Armbian não usar NetworkManager): configurar diretamente via hostapd + dnsmasq. Veja os detalhes no arquivo SETUP_ORANGE_PI.md do projeto.

5.2 — Captive portal (redirecionamento automático)

Para que os alunos não precisem digitar o IP, configurar o dnsmasq para redirecionar qualquer endereço:

sudo bash -c 'cat > /etc/dnsmasq.d/captive.conf <<EOF
address=/#/192.168.4.1
EOF'
sudo systemctl restart dnsmasq

Agora, quando um aluno conectar no WiFi e abrir qualquer página no navegador, será redirecionado automaticamente para a estação.

5.3 — Testar o hotspot

  1. No celular, procurar a rede EstacaoMeteo.
  2. Conectar com a senha meteorologia.
  3. Abrir o navegador — deve redirecionar para a Orange Pi.

Instalar o servidor web

6.1 — Copiar os arquivos

Transferir a pasta estacao-meteorologica/ para a Orange Pi:

# Do seu computador, via SCP:
scp -r estacao-meteorologica/ usuario@192.168.4.1:~/

# Ou via pendrive:
cp -r /media/pendrive/estacao-meteorologica ~/

6.2 — Testar manualmente

cd ~/estacao-meteorologica
python3 app.py

Deve exibir: Acesse: http://192.168.4.1:5000. Abrir no celular para verificar.

6.3 — Iniciar automaticamente no boot

sudo bash -c 'cat > /etc/systemd/system/estacao.service <<EOF
[Unit]
Description=Estacao Meteorologica Educacional
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/home/usuario/estacao-meteorologica
ExecStart=/usr/bin/python3 app.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF'

sudo systemctl daemon-reload
sudo systemctl enable estacao
sudo systemctl start estacao
Ajuste o caminho: substitua /home/usuario/ pelo caminho real do seu usuário na Orange Pi.

6.4 — Endpoints da API

POST /api/dados Recebe leitura dos sensores
GET /api/atual Última leitura
GET /api/dados?horas=6 Histórico das últimas N horas
GET /api/estatisticas?horas=24 Min, max e média do período
GET /api/exportar?horas=24 Download CSV para Excel

Testar tudo junto

Sem o Heltec (simulador)

O projeto inclui um simulador que gera dados realistas — ciclo diário típico do RS com variação de temperatura, umidade inversa, e pressão com ruído:

# Preencher 24h de dados de uma vez (instantâneo):
python3 preencher_db.py

# Simulação contínua (1 leitura por segundo):
python3 simular.py

# Simulação no ritmo real (1 por minuto):
python3 simular.py --intervalo 60

Com o Heltec

  1. Ligar a Orange Pi e esperar o boot (~30s).
  2. Ligar o Heltec V4 — ele conecta automaticamente no WiFi EstacaoMeteo.
  3. O display OLED mostra "WiFi OK" quando conectou.
  4. Após a primeira leitura (60s), os dados aparecem na interface web.
  5. Verificar pelo monitor serial (115200 baud) se os envios estão com [OK].

Checklist de validação

  1. WiFi EstacaoMeteo visível no celular?
  2. Página abre ao conectar no WiFi?
  3. Cards mostram valores numéricos (não "--")?
  4. Gráficos populam ao selecionar período?
  5. Link "Baixar CSV" gera arquivo?
  6. Tendência de pressão aparece após acumular dados?

Uso em sala de aula

Roteiro de aula sugerido

Abertura — 10 min

Apresentar os componentes e explicar o fluxo de dados (sensor → microcontrolador → servidor → celular). Perguntar aos alunos o que acham que influencia a temperatura ao longo do dia e por que a umidade sobe quando a temperatura cai.

Observação — 20 min

Os alunos conectam no WiFi EstacaoMeteo pelos celulares e exploram a interface: leitura atual, gráficos de diferentes períodos, tendência barométrica. Peça que anotem as leituras atuais e comparem com a sensação térmica percebida.

Análise — 15 min

Cada grupo baixa o CSV e abre no Excel ou Google Sheets. Desafios possíveis: calcular a amplitude térmica do dia, identificar o horário mais quente, plotar um gráfico próprio, calcular a média móvel de pressão.

Discussão — 10 min

Relacionar os dados com conceitos de ciências: por que a pressão cai antes da chuva? O que a umidade relativa do ar significa? Como uma frente fria aparece nos dados? Conectar com previsão do tempo e climatologia.

Para turmas avançadas: deixar a estação coletando por uma semana e pedir que os alunos identifiquem a passagem de uma frente fria nos dados — queda de pressão + queda de temperatura + aumento de umidade é a assinatura clássica.

Cuidados práticos

Ligar a Orange Pi 2–3 minutos antes da aula para dar tempo do boot e do hotspot subir. O Heltec pode ficar ligado continuamente por USB ou bateria LiPo. Se a interface não abrir, pedir para o aluno desligar os "dados móveis" no celular — alguns smartphones preferem a rede 4G ao WiFi sem internet.
